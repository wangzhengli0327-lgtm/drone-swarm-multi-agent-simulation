# 架构说明

## 1. 定位

本项目是 60×60 抽象网格中的无人机集群多智能体教学仿真。它验证共享态势、专家会商、候选方案审查、时间步执行和事件触发重规划，不连接真实设备。

## 2. 核心模块

### Streamlit 工作台

`app/drone_swarm_workbench.py` 负责：

- 场景与模型接口配置；
- 仿真主循环；
- 候选方案和动态风险姿态；
- 路径、热力图、指标、会议和报告展示。

### 可复用仿真模块

`app/drone_sim/` 负责：

- `scenario.py`：演示预设；
- `meeting_engine.py`：规则会议与候选方案决策；
- `llm_provider.py`：OpenAI 兼容 API 客户端；
- `llm_agents.py`：结构化模型会议；
- `models.py`：共享数据结构；
- `randomness.py`：可复现随机源。

## 3. 共享态势

每场会议读取同一份结构化状态，包括：

- 任务区位置和覆盖缺口；
- UAV 状态、能量和任务分配；
- 高风险区与近期损失；
- 候选方案指标；
- 当前覆盖主指标和风险姿态；
- 历史会议与事件。

## 4. 专家角色

| 角色 | 职责 |
| --- | --- |
| CoordinatorAgent | 组织会议并汇总决议 |
| ScenarioAgent | 解释任务区与风险区 |
| SwarmStatusAgent | 检查可用、低电量和失效 UAV |
| CoverageAssessmentAgent | 评估累计与滚动覆盖缺口 |
| TaskAllocationAgent | 分配任务区与资源 |
| PathPlanningAgent | 生成抽象路径和建议位置 |
| SafetyReviewAgent | 检查任务遗漏、风险暴露和执行可行性 |

## 5. 会商闭环

一次会议包含：

1. 读取共享态势；
2. 各角色提出意见；
3. 相互质询；
4. 修改候选方案；
5. 安全审查；
6. 从当前候选集中形成决议；
7. 把决议写入仿真执行。

“入选方案”只表示当前候选集中综合评分最高并通过检查，不保证数学全局最优。

## 6. 时间步仿真

1. `t=0` 召开初始规划会议；
2. UAV 从共同起飞点沿抽象路径移动；
3. 每步更新位置、能量、作用范围和任务覆盖；
4. 进入高风险区时按用户概率判断失效；
5. 失效、低电量、滚动覆盖下降、覆盖停滞或风险收益变化可以触发会议；
6. 新决议重新分配剩余资源和路径；
7. 仿真持续到用户设置的最大时间步，目标覆盖率只作为参考线。

## 7. 模型模式

- 纯规则模式：不访问网络；
- 大模型辅助评审：模型意见用于解释和评审，规则评分决定最终方案；
- 大模型决策实验：模型推荐仍需通过覆盖和风险硬约束。

当前实现每场会议最多进行一次逻辑模型调用，不是多个独立模型进程长期运行。

## 8. 输出

- 最终路径与建议位置；
- 时间轴位置回放；
- 当前和累计覆盖热力图；
- 累计与滚动覆盖指标；
- 候选方案、专家争辩和会议纪要；
- 事件时间线和动态风险姿态；
- 单机任务建议；
- Markdown 报告。

## 9. 安全边界

禁止扩展为真实无人机控制、真实航线、武器使用、目标选择、打击路径、突防规避或真实部署建议。
